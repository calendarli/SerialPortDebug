# 固件烧录

底部「发送消息 / 发送文件」旁新增「固件烧录」。首版主要面向 Windows x64。

| 目标 | 连接方式 | 固件 |
| --- | --- | --- |
| STM32 | UART 系统 Bootloader | Intel HEX、BIN |
| STM32 | ST-LINK / SWD | Intel HEX、BIN |
| ESP32 系列 | UART 下载模式 | 一个或多个 BIN |

## 工具准备

- ESP32：应用包含官方 esptool 5.3.1 Windows x64 独立工具，无需安装 Python。
- STM32：先安装 [STM32CubeProgrammer](https://www.st.com/en/development-tools/stm32cubeprog.html)。自动检测标准安装目录；未找到时，在高级设置中选择安装目录里的 `bin/STM32_Programmer_CLI.exe`。不要只复制一个 EXE，其运行依赖完整安装目录。
- 高级设置可指定工具位置、查看版本、重新检测。esptool 自定义路径要求 5.x 原生可执行文件。
- macOS/Linux 可指定对应系统的原生工具，本项目未内置这两个系统的工具，也未完成其硬件验证。

## 烧录步骤

1. 选择芯片系列、UART 或 SWD；刷新并选择串口或 ST-LINK。无需预先在调试区打开串口。
2. 选择固件。STM32 HEX 使用文件内地址；BIN 必须指定起始地址，STM32 默认 `0x08000000`，有 Bootloader 的工程需要按实际布局修改。
3. ESP32 根据工程输出添加「文件 + 地址」。合并 BIN 的起始偏移也必须按生成配置填写；不统一猜测 bootloader、分区表或应用地址。可显式选择 ESP32 型号，也可自动识别。
4. 可先「检测芯片」，详情查看日志。检测不擦写固件，但连接/复位会影响正在运行的程序。
5. 「开始烧录」自动检查工具和文件、连接设备、擦除需要的区域、写入并校验。STM32 可关闭校验；ESP32 保留工具默认写入校验。
6. 完成后查看结果、耗时，必要时导出最近 400 行日志。

STM32 UART 需按具体型号手册配置 BOOT 并复位进入系统 Bootloader。烧录后恢复正常启动配置并手动复位；UART 不支持 SWD 的软件复位命令。ST-LINK 的「复位下连接」还需要 NRST 接线。

ESP32 有自动下载电路时通过 DTR/RTS 进入下载模式；否则选择「手动进入下载模式」，按开发板的 BOOT/RESET 操作。手动模式不会自动生成所有开发板通用的复位时序。

## 串口与任务行为

- 每次运行一个烧录/检测任务，切换页签不停止任务。
- 同一串口正在传输或配置接收文件时，烧录被拒绝，先停止传输/接收。
- 烧录前关闭本应用已有的目标串口，期间拒绝调试打开和写入；其他串口可继续使用。
- 「结束后恢复原串口连接」默认关闭，启用后恢复原来已打开连接的串口参数。自动发送与受影响的指令循环需要重新启动。
- 「停止」终止工具进程树并等待退出后释放串口。固件可能已部分擦写，需要重新完整烧录；没有回滚和断点续烧。
- 退出应用也会停止任务。过程中不要退出或断电。
- 「整片擦除」默认关闭且不持久化，选择后开始烧录前再次确认。它可能删除设备保存的用户数据。

## 支持边界

HEX 验证记录长度、校验和、结束记录、扩展地址及地址重叠；BIN 验证地址、大小及文件间重叠。文件通过检查后生成临时快照用于烧录，结束时清理。

首版仅允许 STM32 主 Flash 地址窗口内的数据，排除 RAM、选项字节等区域；实际芯片容量和写入支持由官方工具检查。HEX/BIN 不一定包含可验证的目标芯片型号，文件结构检查不能证明它适用于当前硬件。ESP32 固件保留 esptool 的芯片、容量和安全检查，不传递 `--force` 等绕过参数。

首版不支持 ELF、ESP32 HEX、USB DFU、外部 Flash loader、解除保护、eFuse、配置安全启动或批量并行烧录。可在现有任务管理下增加后续适配器。

## 开发验证

```text
npm run build
node --test tests/firmware.test.cjs
node_modules/.bin/electron scripts/firmware-ui-smoke.cjs
```

自动测试覆盖固件预检、参数生成、模拟任务成功/失败/取消、资源释放，以及真实 Electron 界面和 preload 接口。它们不会擦写硬件。需要使用实际 STM32 和 ESP32 开发板补充烧录、启动、断线重烧与串口恢复验收。

内置工具来源、版本和校验和见 `resources/firmware/NOTICE.md`。可运行 `python scripts/fetch-esptool.py` 重新获取固定版本。
